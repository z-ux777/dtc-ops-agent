# DTC Ops Agent

A working AI operations layer for a direct-to-consumer brand on a Shopify + Klaviyo style stack.
It does four jobs that eat hours every week at a DTC brand, and it plugs into n8n (or Zapier/Make) over a small HTTP API.

1. **Weekly KPI scorecard.** Revenue, orders, AOV, CVR, MER, new-customer CPA, returning share and gross margin, week over week, with plain-English flags.
2. **48-hour launch check.** When a launch underperforms, it diagnoses in a fixed order (traffic, CVR, offer/AOV, paid efficiency, units, margin) and splits the advice into "act now" and "wait for signal".
3. **Replenishment and win-back segments.** Predicts when each non-subscriber runs out of a product (days of supply x quantity) and builds Klaviyo-ready event payloads for consented profiles only.
4. **Bilingual support agent (English/Spanish).** Detects language, classifies intent, looks up the order with a tool call, drafts a reply, and routes refunds, cancellations and health questions to a human. It never gives medical advice and never promises a refund.

Every outbound action (reply, Klaviyo event, Slack alert) goes to an approval queue. **Nothing in this project sends, refunds or charges anything.**

> **All data is mock.** Every product, customer, order, session, ad-spend and ticket record is generated by
> `data/generate_mock_data.py` (fixed seed, fake `@example.com` emails and 555 phone numbers). Nothing comes from a
> real store, and no real customer, revenue or business figures are included anywhere in this repo.

## Run it

Requires Python 3.10+ and nothing else (standard library only).

```bash
git clone https://github.com/z-ux777/dtc-ops-agent.git && cd dtc-ops-agent
python3 cli.py demo                     # runs every module, writes sample_output/
python3 tests/test_all.py               # 14 tests
python3 cli.py serve 8787               # HTTP API for n8n / Zapier / Make
```

The large mock files (`data/customers.json`, `data/orders.json`, `sample_output/segments.json`) are not committed.
On first run the code generates the mock dataset automatically (same as `python3 data/generate_mock_data.py`,
120 days, seed 7, deterministic), and `cli.py demo` rewrites `sample_output/`.

Other commands: `python cli.py report`, `python cli.py launch SLP-30`, `python cli.py segments`,
`python cli.py chat "Hola, ¿dónde está mi pedido #6510?" C0002`, `python cli.py roi`.

### Optional LLM
Replies are template-based by default, so routing and guardrails are deterministic and testable.
To let a model polish the wording, copy `.env.example`, set `OPENROUTER_API_KEY` and `DTC_OFFLINE=0`.
If the call fails, the agent falls back to the safe template. No key is included.

### n8n
Import the files in `n8n/` (Workflows > Import from file). They call the API at `http://127.0.0.1:8787`.
Change that URL if n8n runs in Docker (for example `http://host.docker.internal:8787`).

Tested in a real n8n 1.95.3: all three workflows import cleanly, and workflow 01 runs end to end when activated (`bash n8n/smoke_test.sh` posts three tickets and gets the routed drafts back).

| Workflow | Trigger | What it does |
|---|---|---|
| 01_support_agent_webhook | Webhook POST /dtc-support | Agent drafts a reply, IF node splits human-review vs approve-and-send, responds to caller |
| 02_weekly_scorecard_launch_watch | Monday 8am | Scorecard + launch check, writes a summary, posts to Slack only if flagged (Slack node disabled until approved) |
| 03_replenishment_to_klaviyo | Daily 7am | Builds "Replenishment Due" events for consented profiles; Klaviyo node disabled with a placeholder key |

## Architecture

```
 Shopify-style data (mock JSON)          n8n / Zapier / Make / chat widget
            |                                         |
            v                                         v
   dtc_ops/data.py  <---------------  dtc_ops/server.py  (stdlib HTTP API)
            |                                         |
   +--------+---------+--------------+----------------+
   |        |         |              |                |
 kpis   launch_   replenishment  support_agent      roi
        monitor   (Klaviyo        (lang -> intent ->
                   payloads)       tool call -> draft -> route)
                                     |
                                   llm.py (OpenRouter, optional; offline stub by default)
                                     |
                          approvals.py  -> approval_queue.jsonl  (human approves every send)
```

API routes: `GET /health`, `GET /api/orders/<id>`, `GET /report/weekly`, `GET /segments/replenishment`,
`POST /launch/check`, `POST /webhook/support`, `POST /roi`. Set `DTC_API_TOKEN` to require an `X-API-Token` header.

## Design choices
- **Deterministic guardrails, optional LLM.** Routing, compliance (no medical claims) and money actions never depend on a model's mood.
- **Human in the loop by default.** Drafts are queued, not sent. That is how I would roll this out at a real brand: shadow mode first, then auto-send only the intents with a clean record.
- **Consent-aware.** Segments carry email/SMS consent and the Klaviyo step filters on it.
- **Stdlib only.** Clone and run in under a minute, no package installs.

## Limits (honest)
- Mock data only; a real deployment would swap `data.py` for Shopify Admin API and Klaviyo API clients.
- Intent detection is keyword-based for testability; in production I would add an LLM classifier and keep the rules as a safety net.
- No auth beyond an optional shared token.
